# Online Boutique Resource Faults

## OB-RES-SOCK-001: Checkout Service Socket Exhaustion During Dependency Fan-Out
- **Affected Services**: checkoutservice, cartservice, productcatalogservice, currencyservice, shippingservice, paymentservice, emailservice
- **Fault Type**: Resource
- **Symptom**: Checkout requests fail intermittently with HTTP 500/503/504 while browsing can remain available; checkoutservice logs show `too many open files`, `cannot assign requested address`, connection-pool exhaustion, or gRPC dial failures; `process_open_fds{job="checkoutservice"}` approaches `process_max_fds`; `node_sockstat_TCP_alloc` or `node_sockstat_TCP_tw` rises; traces show failed connection setup from checkoutservice to cartservice, productcatalogservice, currencyservice, shippingservice, paymentservice, or emailservice
- **Root Cause**: The Go checkoutservice creates dependency connections or clients per request, fails to close them on error paths, or churns short-lived sockets instead of reusing long-lived gRPC channels. Leaked descriptors accumulate in `CLOSE_WAIT`, or connection churn accumulates `TIME_WAIT` sockets and consumes ephemeral ports, eventually preventing the checkout orchestrator from opening new dependency connections
- **Diagnostic Steps**:
  1. In Prometheus, compare `process_open_fds{job="checkoutservice"}` with `process_max_fds{job="checkoutservice"}` and query `node_sockstat_TCP_alloc` plus `node_sockstat_TCP_tw` on the hosting node; correlate exhaustion with `rate(grpc_client_handled_total{grpc_service=~".*(Cart|ProductCatalog|Currency|Shipping|Payment|Email).*",grpc_code!="OK"}[5m])`
  2. Follow a failed checkout trace and identify which checkoutservice client spans fail before reaching a server span; search the same trace IDs in checkoutservice logs for `too many open files`, `connection reset`, `dial tcp`, or pool-acquisition errors
  3. Because checkoutservice uses a minimal image, attach an authorized debug container with `kubectl debug -n <namespace> pod/<checkout-pod> -it --image=<approved-network-debug-image> --target=server --profile=general`; from the shared namespaces, run `ls /proc/1/fd | wc -l`, `ss -tan | awk 'NR>1 {print $1}' | sort | uniq -c | sort -rn`, and `cat /proc/sys/net/ipv4/ip_local_port_range`
  4. Compare affected replicas and recent releases with `kubectl get pods -n <namespace> -l app=checkoutservice -o wide` and `kubectl rollout history deployment/checkoutservice -n <namespace>` to distinguish a pod-local leak from node-wide port pressure
- **Remediation & Mitigation**: Immediate — drain the exhausted checkoutservice pod, capture descriptor and socket-state evidence, restart it to release sockets, and roll back or disable the leaking checkout path; raise file-descriptor limits only as temporary containment after verifying node capacity. Long-term — reuse bounded gRPC client connections, close clients and response streams on every error path, set connection acquisition and idle timeouts, add descriptor and socket-state metrics, test repeated checkout failures for leaks, and preserve checkout idempotency when retries are enabled
