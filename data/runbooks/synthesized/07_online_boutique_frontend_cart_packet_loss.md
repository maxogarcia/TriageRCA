# Online Boutique Network Faults

## OB-NET-LOSS-001: Packet Loss Between Frontend and Cart Service
- **Affected Services**: frontend, cartservice, redis-cart
- **Fault Type**: Network
- **Symptom**: Add-to-cart and view-cart requests fail intermittently while catalog browsing continues to work; frontend returns HTTP 500/503 or reports gRPC `UNAVAILABLE` and `DEADLINE_EXCEEDED`; `rate(node_netstat_Tcp_RetransSegs[5m]) / rate(node_netstat_Tcp_OutSegs[5m])` rises on the relevant nodes; cart latency becomes bimodal; traces show frontend cart client spans with long gaps or errors and, for fully lost connections, no matching cartservice server span
- **Root Cause**: Packet loss on the frontend-to-cartservice gRPC path drops TCP segments or connection handshakes. TCP retransmission delays some calls and causes others to exceed their deadline; because cartservice persists data through redis-cart, unsafe application retries can also create confusing repeated mutations unless operations and retry behavior are designed for idempotency
- **Diagnostic Steps**:
  1. In Prometheus, calculate `rate(node_netstat_Tcp_RetransSegs[5m]) / rate(node_netstat_Tcp_OutSegs[5m])` for nodes hosting frontend and cartservice, inspect `rate(node_network_transmit_drop_total[5m])`, and correlate with `rate(grpc_client_handled_total{job="frontend",grpc_service=~".*Cart.*",grpc_code=~"UNAVAILABLE|DEADLINE_EXCEEDED"}[5m])`
  2. Compare successful and failed frontend → cartservice traces; missing cartservice server spans indicate handshake or pre-delivery loss, whereas long client spans with short server spans indicate retransmission delay on the path; correlate trace IDs with frontend connection-reset and cartservice cancellation logs
  3. Production frontend and cart images may not include `tc`, `ss`, or `ping`; attach an authorized ephemeral container with `kubectl debug -n <namespace> pod/<frontend-pod> -it --image=<approved-network-debug-image> --target=server --profile=general`, then run `tc -s qdisc show dev eth0`, `ss -ti dst <cart-pod-ip>`, and, when ICMP is permitted, `ping -c 50 <cart-pod-ip>` from the shared frontend network namespace
  4. Verify endpoint and node scope with `kubectl get endpointslice -n <namespace> -l kubernetes.io/service-name=cartservice -o wide` and `kubectl get pods -n <namespace> -l 'app in (frontend,cartservice)' -o wide`
- **Remediation & Mitigation**: Immediate — remove the verified loss injection, route away from impaired endpoints or drain an unhealthy node, and limit automatic retries to operations proven safe so cart mutations are not duplicated. Long-term — use bounded retries with jitter and explicit idempotency semantics, enable outlier detection for failing cart endpoints, monitor retransmission ratio and gRPC error codes, test packet loss in staging, and keep frontend-to-cart deadlines aligned with the user request budget
