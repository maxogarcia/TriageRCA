# Online Boutique Resource Faults

## OB-RES-DISK-001: Node Disk Stress Degrades Product Catalog Availability
- **Affected Services**: productcatalogservice, frontend, recommendationservice
- **Fault Type**: Resource
- **Symptom**: Product lists and product-detail pages load slowly or fail while unrelated operations on other nodes may remain healthy; frontend and recommendationservice observe gRPC `DEADLINE_EXCEEDED` or `UNAVAILABLE` from productcatalogservice; `rate(node_disk_io_time_seconds_total[5m])`, disk await time, or node filesystem consumption rises; kubelet or container-runtime logs may report I/O latency, image/filesystem errors, or `DiskPressure`
- **Root Cause**: An authorized disk-stress workload, container-runtime logging surge, or node filesystem exhaustion saturates the node hosting productcatalogservice. The standard productcatalogservice deployment uses a read-only root filesystem, so application writes to its root layer are not the normal cause; impact instead comes from node/container-runtime I/O, an added writable volume, or deployment drift, and may be most visible during logging, startup, or restart operations
- **Diagnostic Steps**:
  1. In Prometheus, query `rate(node_disk_io_time_seconds_total[5m])`, `node_filesystem_avail_bytes`, `node_filesystem_files_free`, and `kube_node_status_condition{condition="DiskPressure",status="true"}` for the node hosting productcatalogservice; correlate the anomaly with catalog gRPC latency and error rate
  2. Inspect frontend → productcatalogservice and recommendationservice → productcatalogservice traces; correlate high catalog span duration or missing spans with `kubectl logs -n <namespace> <productcatalog-pod> --since=30m` and node/container-runtime events rather than assuming the application rereads its catalog file on every request
  3. Confirm the hardened filesystem and mounted writable paths with `kubectl get pod -n <namespace> <productcatalog-pod> -o jsonpath='{.spec.containers[0].securityContext.readOnlyRootFilesystem}{" volumes="}{.spec.volumes}'`; identify placement with `kubectl get pod -n <namespace> <productcatalog-pod> -o wide`
  4. Inspect node I/O only through an authorized node-debug workflow: `kubectl describe node <node>` and `kubectl debug node/<node> -it --image=<approved-node-debug-image> --profile=sysadmin`; within the debug environment, run `iostat -xm 1 3` and `df -h /host` when those tools are approved
- **Remediation & Mitigation**: Immediate — stop the verified stress workload or runaway node-level writer, rotate/offload container-runtime logs, and cordon or drain the unhealthy node according to disruption policy; reschedule productcatalogservice and restore traffic only after latency, node condition, and free-space checks recover. Long-term — preserve the read-only root filesystem, bound node log retention, set ephemeral-storage requests and limits for writable workloads, isolate deliberate stress tests, alert on disk latency and `DiskPressure`, and exercise safe node evacuation in staging
