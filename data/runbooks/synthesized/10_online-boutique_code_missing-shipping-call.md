# Online Boutique Code-Level Faults

## OB-CODE-FUNC-001: Checkout Omits the ShipOrder Call
- **Affected Services**: checkoutservice, paymentservice, shippingservice
- **Fault Type**: Code-level
- **Symptom**: `PaymentService/Charge` succeeds and returns a transaction ID, but the checkout trace lacks `ShippingService/ShipOrder`; if the defective code continues constructing a response, `shipping_tracking_id` may be empty or invalid even though checkout appears successful. If custom instrumentation exports successful checkout, charge, and shipment counters, inspect their rate gap; otherwise derive the signal from trace and structured-log counts
- **Root Cause**: A refactor, incorrect conditional, or early return skips checkoutservice's required `ShipOrder` RPC after payment succeeds. In the stock application, `ShipOrder` accepts an address and cart items and returns a generated tracking ID; shippingservice is a mock and does not persist shipment records, so a missing call cannot be diagnosed through a built-in shipment database
- **Diagnostic Steps**:
  1. If custom instrumentation exports `checkout_place_order_success_total`, `payment_charge_success_total`, and `shipping_ship_order_requests_total`, inspect it; otherwise count the corresponding OpenTelemetry spans or structured log events over the same window and segment the checkout-to-shipping gap by checkoutservice revision
  2. Compare one affected and one healthy trace; verify that the affected checkout trace contains a successful `PaymentService/Charge` span and transaction ID but lacks `ShippingService/ShipOrder`. Review `kubectl logs deployment/checkoutservice -n <namespace> --since=30m` and `kubectl logs deployment/shippingservice -n <namespace> --since=30m`; correlate by trace context and time because the stock `ShipOrderRequest` and shipping log do not contain an order ID
  3. Check `kubectl rollout history deployment/checkoutservice -n <namespace>` and the running image. In staging, submit one controlled order and verify that the trace includes `ShipOrder` and that `PlaceOrderResponse.order.shipping_tracking_id` is nonempty; do not look for a matching shipment record because stock shippingservice only generates a notional tracking ID
- **Remediation & Mitigation**: Immediate — stop or roll back the defective checkoutservice revision and identify affected transactions from payment and checkout trace/log evidence; because stock shippingservice has no persistent shipment ledger or idempotency key, issue compensating shipping calls only through an audited procedure that has the original address/items and an external deduplication record. Long-term — model checkout as an explicit state machine or saga with durable step state, add an order-linked idempotency contract before automated replay, instrument named workflow spans/counters, and test that every successful response contains a tracking ID after a completed `ShipOrder`
